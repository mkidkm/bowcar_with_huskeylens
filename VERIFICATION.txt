v0.1 색/얼굴 업로드 코드 검증 — 2026-10-12

완료:
  Python 3.8 문법 호환 검사.
  두 Python 파일의 main 실행 시 upload_code()가 각각 1회 호출되는지 검사.
  설정 파일의 USB 포트/FQBN이 업로드 메서드로 전달되는지 확인.
  색 프로그램의 NeoPixel 라이브러리 설치 호출 확인(실제 설치는 모의 처리).
  Python으로 생성한 두 .ino를 호스트 C/C++ 컴파일러로 빌드함.
  제조사 원본 HUSKYLENS 라이브러리와 실제 프레임/체크섬을 쓰는 I2C
  모의 장치로 아래 동작을 확인함.

색/네오픽셀:
  ID1=빨강, ID2=초록, ID3=파랑, LED 4개와 D9 설정.
  밝기 50, 다른 ID/ID0/대상 없음에서 꺼짐.
  동시에 보이는 대상 중 큰 사각형 선택.
  통신 실패에서 꺼짐, 재연결 후 색 갱신.
  모든 경우 모터 정지 유지.

얼굴 추종:
  중앙 전진, 왼쪽/오른쪽 조향, x=134/135/185/186 경계.
  얼굴 너비 120픽셀에서 정지, 119픽셀에서 전진 허용.
  다른 ID/학습하지 않은 얼굴 무시.
  얼굴 소실 및 통신 실패에서 정지, 통신 복구 후 동작 재개.
  Face Recognition 모드와 ID1 사각형 요청 명령 사용 확인.

NeoPixel 검증 범위:
  Adafruit_NeoPixel 공식 master 소스(library.properties 1.15.5)의 헤더와
  색 버퍼/밝기 처리 코드를 사용함. MCU용 신호 타이밍 show() 함수만
  호스트 시험에서 아무 신호도 출력하지 않는 함수로 바꿔 실행함.
  따라서 RGB 채널 선택/버퍼 처리 검증이며 실제 LED 신호·출력 검증은 아님.

환경 한계:
  의존성은 bowcar 1.3.4 공개 소스와 검증용 pyserial import 모의 모듈을
  사용함. 실제 PyPI 의존 패키지는 사용자 PC에서 설치해야 함.
  초기 검증에서는 실제 AVR 빌드/Flash·SRAM 사용량/USB 업로드/
  허스키렌즈 인식 성능/네오픽셀 출력/전원/주행을 확인하지 못했음.

ATmega328P 설정 추가 검증 — 2026-10-12

  공통 FQBN을 arduino:avr:uno로 변경함. MiniCore를 사용하지 않음.
  Arduino CLI 1.4.1, Arduino AVR Boards 1.8.8, bowcar 1.3.4,
  Adafruit NeoPixel 1.15.5 환경에서 두 build_program()의 생성 코드를
  임시 폴더에 저장하여 compile_code()로 컴파일만 수행함.
  두 생성 코드가 기존 generated 폴더의 .ino와 동일함을 확인함.

  색 인식: 컴파일 통과, Flash 9,416바이트, 정적 SRAM 936바이트.
  얼굴 추종: 컴파일 통과, Flash 8,272바이트, 정적 SRAM 914바이트.
  SRAM 수치는 전역 변수 기준이며 실행 중 동적 할당과 스택을 포함하지 않음.

  실제 보드 업로드/MCU 종류·부트로더/허스키렌즈 인식/네오픽셀 출력/
  전원/주행은 확인하지 않음. 설치 및 업로드 명령은 실행하지 않음.

시작 모드 전환 추가 검증 — 2026-10-12

  두 예제의 생성자 다음에 begin_huskylens() 호출을 추가함.
  setup()에서 색 프로그램은 Color Recognition, 얼굴 프로그램은
  Face Recognition으로 전환하며, 실패 시 loop()에서 기존 간격으로 재시도함.
  연결·모드 설정 로직은 시작과 재연결에서 같은 함수를 사용함.
  Python 파일과 generated 폴더의 두 .ino를 함께 갱신함.

  Arduino AVR Boards 1.8.8 / arduino:avr:uno 컴파일 통과:
    색 인식: Flash 9,450바이트, 정적 SRAM 936바이트.
    얼굴 추종: Flash 8,332바이트, 정적 SRAM 914바이트.
  현재 Python 파일의 Python 3.8 문법 검사 통과.

  호스트 모의 시험 6개 통과(색/얼굴 각각 정상 시작, 카메라 연결 지연,
  모드 설정 응답 실패). loop() 전에 모드 전환을 시도하며, 실패 중에는
  모터 정지/검출 요청 없음, 재시도 후 복구, 재연결 시 모드 재설정을 확인함.
  안정적으로 연결된 loop()에서는 모드 설정 명령을 반복하지 않음.
  MSVC 호환을 위한 임시 제조사 소스 사본과 Arduino/Wire/NeoPixel 모의
  장치를 사용함. 배포한 제조사 라이브러리는 변경하지 않음.
  실제 USB 업로드와 허스키렌즈 화면의 모드 전환은 아직 확인하지 않음.
