검증 결과 — 2026-10-08

통과: Python unittest 8항목, 그 안의 C/C++ 호스트 실행 4개.

Python 검증:
  1. 보드 FQBN 미지정 시 컴파일·업로드를 진행하지 않음.
  2. 기본 .ino 생성 동작에서 업로드 명령이 호출되지 않음.
  3. 알고리즘/ID/타임아웃/극성 등 잘못된 설정을 거부함.
  4. 잘못된 모터 속도 표현식을 거부함.
  5. 확장 모듈과 예제의 Python 3.8 문법 호환성을 검사함.
  6. Arduino CLI 실패 메시지를 호출자에게 전달함.
  7. 사용자 지정 FQBN, 포트, 제조사 라이브러리 경로를 CLI에 전달함.
  8. 아래의 제조사 라이브러리 + 생성 코드 호스트 검증을 수행함.

호스트 C/C++ 검증:
  제조사 HUSKYLENS.h 및 HuskyLensProtocolCore.c 원본을 사용함.
  GCC로 프로토콜 C 코드를 컴파일하고 G++로 생성 .ino를 포함한 실행 파일을
  빌드함. Arduino API와 I2C 하드웨어는 tests/host의 모의 장치로 대체함.
  모의 장치는 실제 제조사 프로토콜의 프레임/체크섬/명령/인식 결과를 응답함.

  connection_check:
    I2C 주소 0x32, 연결 성공, 인식 결과, 대상 없음, 좌표 초기화,
    모터 정지 유지, Wire 타임아웃 설정.
  follow_object:
    중앙 전진, 좌우 조향, 사각형 너비 기준 정지, 다른 ID 무시,
    속도 범위 제한, 전진/후진 방향 신호, 오래된 결과에 따른 지연 중 정지,
    가장 큰 사각형 선택, 대상 소실 시 정지, 응답 실패 시 정지,
    재시도 간격, 통신 복구, 알고리즘 설정 실패 시 정지.
  tag_actions:
    학습 ID 2/3 회전, ID 4 전진, 동시 검출 시 ID 1 정지 우선,
    ID 0 제외, 정의되지 않은 ID 정지, 학습된 사각형 요청 명령.
  line_follow:
    중앙/좌/우 선 화살표에 따른 속도 계산, 다른 ID 무시,
    잘못된 좌표 제외, 화살표 소실 시 정지/좌표 초기화, 화살표 요청 명령.

추가 확인:
  Python 해시 시드를 달리한 두 프로세스에서 생성 코드가 동일함.
  제공한 제조사 소스 5개는 원본 Git blob SHA와 바이트 단위로 일치함.

검증 환경의 한계:
  이 환경에서 PyPI wheel 다운로드가 제한되어 bowcar 1.3.4의 공개 GitHub
  소스(255d807123353071e99543de7b1fdfaf8e8cffbc)를 사용함.
  실제 포트에 접근하지 않도록 pyserial의 import/포트 목록 부분을 검증용
  모의 모듈로 대체함. 배포 묶음에는 이 모의 Python 의존성을 넣지 않았으며,
  사용자 환경은 requirements.txt로 실제 PyPI 패키지를 설치해야 함.
  Python 3.8 문법 검사는 실제 Python 3.8 런타임 실행 시험과 구별됨.

  AVR 컴파일러/Arduino CLI/실제 바우카/허스키렌즈를 사용할 수 없었으므로
  실제 MCU용 컴파일·메모리 사용량·USB 업로드·배선·전원·모터·카메라 동작은
  확인하지 못함. 호스트 시뮬레이션은 이러한 실제 보드 시험을 대체하지 않음.

사용자 환경에서 소프트웨어 시험을 다시 실행하려면:
  python -m pip install -r requirements.txt
  python -m unittest discover -s tests -v

호스트 C/C++ 시험에는 gcc와 g++가 추가로 필요함. 둘 중 하나가 없으면
해당 시험이 skip되므로, 실제 보드용 컴파일은 Arduino IDE 또는 CLI의
검증/컴파일 기능으로 별도로 확인해야 함.
